## 3. 백업
- D1은 **Time Travel(최근 30일 아무 시점으로 복원)** 이 기본 제공된다(별도 설정 없음). 실수로 지웠거나 배포 사고가 났을 때 쓴다.
  - 확인: `npx wrangler d1 time-travel info gildongmu-kids`
  - 복원: `npx wrangler d1 time-travel restore gildongmu-kids --timestamp=<ISO시각>` (복원은 DB 전체를 그 시점으로 되돌리므로 그 뒤 데이터는 사라진다. 복원 전에 아래 내보내기를 먼저 해 둔다)
- 30일보다 오래 보관하려면 주 1회 내보내기(집 PC에서 작업 스케줄러로 실행 가능):
  `npx wrangler d1 export gildongmu-kids --remote --output=backup-YYYYMMDD.sql`
  - 내보낸 파일에는 개인정보가 있으므로 암호화 폴더에 두고, **법정 보관기간(200일)이 지난 자료가 백업에 남지 않게** 백업은 최근 4~8주분만 보관한다.
- 처리방침에 "백업 보관 기간"을 한 줄 적는다(자동 30일 + 선택 내보내기).

## 4. 모니터링 (대시보드에서 사용자가 설정)
1. Cloudflare → Notifications → Add: ① Workers 오류율/사용량 급증 ② D1 사용량(읽기·쓰기) ③ 결제(Billing) 사용량 알림 — 받는 곳은 이메일.
2. Workers → gildongmu-kids → Observability(로그) 켜기(오류 원인 추적).
3. 외부 생존 확인(무료): `/health` 를 5분마다 호출하는 모니터(UptimeRobot 등) → 실패 시 이메일. 집 PC 작업 스케줄러에서 `curl` 로 확인하고 실패 시 알림을 보내도 된다.
4. 운영 지표: `GET /admin/mx?days=14` + 헤더 `x-admin-key`(워커 변수 `ADMIN_KEY` 설정 후). 가입·연결·호출·구독 횟수.

## 5. 출시 전 위험 (중요)
- **요금제 확인**: 무료(Free) 요금제는 D1 쓰기 하루 10만 행 한도. 자녀 1명이 하루 수백 건 쓰기를 만들 수 있어 **수백 명이 되기 전에 Workers Paid($5/월)** 여야 한다. 대시보드 Billing에서 현재 요금제 확인. → 사용자 확인(11-04): 월 약 5천 원대 결제 중 = Workers Paid로 보임(플랜 이름은 Billing에서 한 번 더 확인). Paid 포함량은 D1 쓰기 월 5천만 행·읽기 월 250억 행·요청 월 1천만 건이고, 넘으면 사용량만큼 추가 과금.
- s431 워커(구독·지표) 배포 후 `meta.schema` 가 `s431-1` 로 바뀌는지 확인.
