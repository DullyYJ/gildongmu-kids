# HANDOFF - Gildongmu Kids (길동무 키즈)

> 이 저장소는 길동무(subway-app) 저장소와 분리된 새 프로젝트다. 길동무 저장소에는 이 프로젝트 파일을 올리지 않는다. 길동무와 연동해야 하는 부분은 INTEGRATION.md에 모은다. 설계 배경과 법적 검토는 DESIGN.md.

## 0. 상시 규칙 (모든 작업에 적용)
- 100% 최신 네이티브. WebView/레거시 금지. 메인 스레드 부하 0, 무거운 일은 백그라운드. 상용 수준 완성도.
- 앱은 그리기만 한다. 판단/계산/화면 정의는 엔진(서버)이 한다.
- 질문 없이 자율 진행. 답변은 한국어로 짧게. 엔진 워커 파일이 바뀌면 최신 파일을 사용자에게 전달.
- 부모에게 보이는 위치는 정확한 GPS 좌표(날씨 조회에서만 반올림). 서울 기본 위치 폴백 없음.

## 1. 개념
- 길동무: 출퇴근 청년과 부모가 쓰는 기존 앱(부모 측). 길동무 키즈: 자녀 전용 다마고치형 앱. 길동무 친구들이 해변/공원 장면을 돌아다니고 밥, 응가, 공부, 잠 같은 돌봄을 한다.
- 핵심: 자녀 폰 위치를 연결된 부모가 길동무에서 본다. 연결은 QR 또는 비밀키.

## 2. 현재 구현 (APK는 GitHub Releases의 latest)
- 하단 탭: 가족대화 / 노선도 / 홈 / 퀘스트 / 설정.
- 홈: 맨 위 흐르는 응원 문구(높이 35dp) -> 날씨 한 문장("아라동 7도예요. 맑아요.", 박스 없음) + 바람/체감 -> 장면(길동무 서버 /scene) -> "길동무 친구들과 놀기" 박스(같이 놀아요=화면에 나온 친구, 휴식 중=없는 친구) -> 별도 "길동무 친구들 꾸미기" 버튼.
- 꾸미기 팝업: 위에 고른 친구가 걷는 모습(AvatarView), 친구 선택 칩, 모자/옷/소지품 탭. 아이템은 자리표시(곧 만날 수 있어요).
- 퀘스트 탭: 왼쪽 자녀 미션(부모가 보낸 것), 오른쪽 부모님 미션(내가 부모에게 보낸 것). 지금은 이 기기에만 저장한다(연동은 INTEGRATION.md).
- 노선도: 길동무와 같은 화면 그리개로 버스/지하철. 버스는 서버 part "b" 화면(지도+정류장 카드, GPS 기준, 20초 갱신, 즐겨찾기/별명/순서 끌기/당겨서 새로고침/좌우 밀기). 지하철은 역을 누르면 바로 시간표. 출발/도착 버튼은 없다. 노선 상세(br.*)는 미구현.
- 설정: 위치 공유 토글, 다크 모드, 부모 연결(QR/비밀키 표시). 첫 실행 때 부모/자녀 동의 창.

## 3. 빌드와 배포
- 소스는 bundle/*.txt 파일을 push하면 CI(build-apk.yml)가 풀어서(=== FILE/EDIT: 경로 ===, @@ old/@@ new, old는 정확히 1번만 일치) 빌드하고 APK를 latest 프리릴리스에 올린 뒤 번들을 지운다. bundle 외 푸시는 CI를 돌리지 않는다.
- 길동무 저장소(native-shell 브랜치)의 ScreenView, ScreenCore, SceneCore, Chars, 지도/타일 코드와 캐릭터 시트(assets/chars3d)는 CI가 읽기 전용으로 가져와(com/dullyyj/subway, gitignore) 쓴다. app/kids-patch/swaps.txt와 KidsActs3.java.txt가 빌드 때 그 파일을 패치한다.

## 4. 코드 지도 (app/src/main/java/com/dullyyj/kids)
- Engine: 상태(친구, 위치, 동의, 가족대화, 퀘스트), 모든 화면 JSON, 행동 처리. Poke: 장면과 엔진 사이 다리(상태, 화면에 나온 친구 목록). Store: 작은 저장소.
- Renderer: 블록형 화면(가족대화, 설정, 꾸미기 팝업) 그리기. SvHost/ScreenView: 길동무와 같은 서버 주도 화면. MapPane: 노선도(버스/지하철/시간표). TabBar, AvatarView, Wire(네트워크), MainActivity.

## 5. 남은 일
- 노선 상세(br.*), 지하철 지역 칩, 꾸미기 실제 아이템, 퀘스트 연동, 키즈 워커+D1, 부모 쪽 QR/비밀키 연결, 처리방침/법적 검토(DESIGN.md 9장).

# INTEGRATION - 길동무 <-> 길동무 키즈 연동 (제안, 아직 구현 전)

원칙: 판단은 서버가 하고 앱은 그린다. 아래 엔드포인트 이름은 제안이다. 키즈 전용 새 워커(gildongmu-kids-api)와 D1(kids-db)로 분리하고, 기존 엔진(route-v2)은 건드리지 않는다.

## 1. 지금 키즈 앱이 길동무 서버에서 읽어 쓰는 것 (변경 없이 재사용)
- route-v2 POST /scene: 장면(cast, 날씨 look). POST /screen/map: 노선도 part h, stn, tt, b(버스). POST /next-train: 시간표 보조.
- 동네 이름: gentle-lab-7e47subway-api 워커의 /kakao-local(coord2regioncode).
- 위 서버가 바뀌면 키즈도 영향을 받는다. 응답 형식을 바꿀 때는 키즈 호환 확인.

## 2. 길동무(부모 앱)에 추가해야 하는 것
1. 연결: QR 스캔 또는 비밀키 입력 화면. 키즈 QR 형식 gildongmu-kids://pair?c=<child_id>&k=<8자리 키>(10분 유효). 제출 -> POST /pair/claim -> 서버가 검증, 부모 키와 자녀를 연결, 키 폐기, 시도 횟수 제한. 부모 최대 2명. 부모 신원은 설치별 랜덤 키 + 복구 코드(DESIGN.md 9장).
2. 위치 알약: 홈 화면에 GET /kids/pills 결과만 그린다(문구, 색, 신선도는 서버가 계산). 알약을 열면 서버가 watch 상태로 바꿔 자녀 전송 주기를 높인다.
3. 가족대화: 연결된 가족끼리 텍스트만, 서버 보관 7일. 키즈 가족대화 탭과 같은 대화방.
4. 퀘스트(아래 3장): 자녀에게 미션 보내기, 자녀가 보낸 미션 받기/완료 표시.
5. 동의 기록: 부모가 연결할 때 동의 화면, 동의 일시와 약관 버전을 서버에 기록. 해제/삭제 시 위치 즉시 파기.

## 3. 퀘스트 연동 설계
- 키즈 퀘스트 탭: 왼쪽 자녀 미션(부모 -> 자녀), 오른쪽 부모님 미션(자녀 -> 부모). 지금은 키즈 기기에만 저장(Engine의 quests: i, k="c"|"p", x 내용, s 완료, t 시각).
- 모델(서버): quest{id, family_id, dir:"p2k"|"k2p", text(100자), created_at, status:"open"|"done", done_at}.
- 부모 -> 자녀: 길동무에서 POST /kids/quest(dir p2k) -> 키즈가 GET /kid/quests로 받아 자녀 미션에 표시 -> 자녀가 누르면 POST /kid/quest/done -> 서버가 부모에게 완료 표시(알림은 검토).
- 자녀 -> 부모: 키즈에서 POST /kid/quest/send(dir k2p) -> 길동무가 받은 미션 목록에 표시 -> 부모가 완료 처리 POST /kids/quest/done -> 키즈 부모님 미션에 "부모님이 해냈어요" 반영.
- 갱신: 키즈는 앱을 켤 때와 퀘스트 탭에서 조회. 필요하면 FCM 신호 전용 메시지(내용 없음)로 깨운다.
- 길동무 쪽 화면(미션 보내기, 받은 미션)은 서버 주도 화면(ScreenCore)으로 서버가 정의한다.

## 4. 키즈 워커가 맡을 것
- 등록(child_id, child_secret), 페어링 코드 발급/검증, POST /kid/loc(응답에 nextSec), 최신 위치 1건만 보관, 가족대화 7일 만료 삭제, 퀘스트 저장과 완료, 접근 기록, 해제 시 파기.

## 5. 결정/확인 필요
